# Documentation Standards

## Overview

This document defines the standards for creating and maintaining engineering
documentation within the RideShare Platform repository.

Consistent documentation improves collaboration, supports knowledge sharing and
ensures the platform's evolution from a single-region Amazon EKS deployment to
a production-oriented, multi-region AWS platform is clearly documented.

---

## Objectives

The Documentation Standards are intended to:

- maintain clear and consistent engineering documentation
- improve the discoverability of information
- keep documentation aligned with the platform
- support knowledge sharing across the repository
- provide a reliable reference for future platform evolution.

---

# Documentation Principles

Engineering documentation should be:

- accurate and up to date;
- clear and concise;
- easy to navigate;
- written for long-term maintainability; and
- reviewed alongside significant engineering changes.

---

# Documentation Expectations

Documentation should:

- include a README for major directories;
- explain the purpose and responsibilities of components;
- reference related documentation where appropriate;
- avoid duplicate content; and
- remain consistent with the platform architecture and governance documents.

Significant architectural decisions should be documented using Architecture
Decision Records (ADRs).

---

# Documentation Maintenance

Documentation should evolve together with the platform.

When significant architectural, operational or engineering changes occur,
affected documentation should be reviewed and updated to reflect the current
state of the platform.

Outdated or superseded documentation should be revised or removed to maintain a
single, reliable source of truth.

---

# Relationship to Other Governance Documents

This document defines how engineering documentation is maintained within the
RideShare Platform repository.

Related governance documents include:

- **Platform Standards**, which define the engineering standards applied across
  the platform.
- **Cloud Conventions**, which define the conventions for AWS resources.
- **Repository Standards**, which define how the repository is organized.
- **Platform Inventory**, which records the platform components documented in
  the repository.
